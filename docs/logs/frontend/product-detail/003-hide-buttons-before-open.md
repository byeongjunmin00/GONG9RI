# 003-hide-buttons-before-open — 오픈예정 상품 구매/신설 버튼 완전 숨김 + 액션 버튼 순서 조정 (로그)

## Attempt 1 — 2026-08-19 ✅ PASS
- 시도: (사용자 리포트) 오픈예정(`openAt`이 미래) 상품 상세 페이지에서 "혼자 구매하기"/"신규 팀
  신설하기" 버튼이 회색 비활성(`disabled`) 상태로 계속 화면에 보여서, 사용자가 "버튼이 계속
  보인다"고 지적. `js/product.js`의 `updateOpenAtNotice()`/`updateCreateTeamButtonState()`에서
  기존 `disabled` 처리에 `hidden = true`를 추가해 오픈 전에는 두 버튼이 DOM에서 완전히 안
  보이게 바꾸고, 오픈되면(`openAt` 경과) 다시 `hidden = false`로 복귀시킨다. 이어서 사용자가
  "공유하기 버튼과 쇼핑하기 버튼을 앞으로 배치 조정해달라"고 추가 요청해, `product.html`의
  `.product-actions` 버튼 순서를 [혼자구매/신설/공유/쇼핑] → [공유/쇼핑/혼자구매/신설]로 변경.
  오픈예정 상품처럼 앞 두 버튼이 숨겨져도 공유·쇼핑 버튼이 자연스럽게 앞에 남게 하기 위함.
- 결과: 로컬 MySQL/Redis(Docker Desktop 미기동)가 없어 실제 백엔드 대신 스크래치패드의 임시
  PowerShell 목업 서버로 `GET /api/products/999`(openAt=2099, 오픈예정)와 `/998`(openAt=2020,
  이미 오픈)을 만들어 두 케이스 모두 브라우저에서 확인. 999는 구매/신설 버튼이 DOM에서 완전히
  사라지고 "계속 쇼핑하기" 링크만 액션 영역에 남으며 오픈예정 안내 배너가 정상 노출됨. 998은
  두 버튼 모두 정상 노출되고, 순서가 [쇼핑→구매→신설]로 바뀐 것을 확인. 별도 자동 테스트
  스위트는 없다(정적 JS).
- 증거(브라우저 스크린샷):
  - `product.html?id=999`: "오픈예정 상품입니다(2099. 1. 1. 오전 12:00:00 공개 예정). 그
    전까지는 구매·팀 신설이 불가합니다." 배너 노출 + 액션 영역엔 "계속 쇼핑하기" 링크만 존재
    (구매/신설 버튼이 DOM에 없음, accessibility tree에도 잡히지 않음).
  - `product.html?id=998`: 배너 없음, 액션 영역에 "계속 쇼핑하기 · 혼자 구매하기 · 신규 팀
    신설하기" 순서로 3개 모두 노출.

## Attempt 2 — 2026-08-19  ✅ PASS (Attempt 1 순서 변경 되돌림)
- 시도: 사용자가 Attempt 1의 버튼 순서 변경을 오해로 지적 — "순서를 바꾸라는 게 아니라, 오픈
  전 버튼이 사라져서 텅 비어 보이니 남은 두 버튼을 앞으로 당기라는 뜻이었고, 오픈되면 원래
  순서로 돌아가야 한다"는 취지. `.product-actions` 자식들은 이미 `.btn[hidden] { display: none; }`
  (components.css 상단)로 `hidden` 요소가 flex 흐름에서 완전히 빠지게 돼 있어, DOM 순서를
  원래대로([혼자구매/신설/공유/쇼핑])만 되돌리면 오픈 전엔 안 숨겨진 나머지 버튼(공유하기·
  계속 쇼핑하기)이 자동으로 맨 앞에 당겨져 보이고, 오픈되면 원래 4개 순서 그대로 복원된다 —
  별도 JS 순서 로직 불필요. `product.html`의 `.product-actions` 마크업을 Attempt 1 이전 순서로
  되돌렸다(`js/product.js`의 hidden 토글 로직은 Attempt 1 그대로 유지).
  또한 사용자가 "카카오톡 공유하기도 빠졌다"고 지적했는데, 확인 결과 `kakaoShareBtn.hidden`은
  `setUpKakaoShare()`(`kakaoJsKey` 유무로만 결정, `js/product.js:313-322`)에서만 토글되고
  `updateOpenAtNotice`/`updateCreateTeamButtonState`(오픈예정 로직)는 이 값을 건드리지 않는다 —
  Attempt 1 스크린샷에서 공유 버튼이 안 보인 건 목업 상품 데이터에 `kakaoJsKey`를 넣지 않아서였고
  (오픈 여부와 무관하게 원래도 숨겨짐), 오픈예정 로직이 공유 버튼을 새로 숨기게 된 건 아니다.
- 결과: 같은 목업 서버(`/api/products/999`, `/998`)로 재확인. 999(오픈예정): "계속 쇼핑하기"만
  액션 영역 맨 앞에 노출(공유 버튼은 목업에 `kakaoJsKey`가 없어 여전히 숨김, 기존 동작대로).
  998(오픈됨): "혼자 구매하기 → 신규 팀 신설하기 → 계속 쇼핑하기" 순서로 Attempt 1 이전 원래
  순서와 동일하게 복원됨을 확인.
- 증거(브라우저 스크린샷):
  - `product.html?id=999`: 액션 영역에 "계속 쇼핑하기" 링크만 맨 앞에 노출.
  - `product.html?id=998`: 액션 영역이 "혼자 구매하기 · 신규 팀 신설하기 · 계속 쇼핑하기" 순서
    (공유 버튼은 목업 데이터 한계로 미노출, 코드상 오픈 여부와 무관함은 정적 분석으로 확인).
