# 001-ticker-layout-and-auth-button — 헤더 검색창/실검 티커 레이아웃 흔들림 + 로그인 버튼 통합 (로그)

사용자가 채팅으로 직접 지시한 UI 버그 수정 작업이라 별도 계획 문서(docs/dev/ongoing/) 없이
Plan 단계를 건너뛰고 진행했다 (작은 CSS/마크업 수정, 되돌리기 쉬움).

## Attempt 1 — 2026-08-19 ❌ 반려 (사용자가 명시적으로 되돌림)
- 시도: 실검 티커에 고정 `width: 180px` 적용 (기존엔 `max-width`만 있어서 검색어 글자 수에
  따라 티커 자체 너비가 변해 옆 검색창이 밀리는 문제가 있었음)
- 결과: 검색창은 안 흔들리게 됐지만, 짧은 검색어일 때 티커 안에 빈 공간이 크게 남음
- 사용자 피드백: "실검 버튼 공백이 너무 많잖아" → 반려

## Attempt 2 — 2026-08-19 ❌ 반려 (겹침 버그)
- 시도: 티커를 flex 흐름에서 빼서 `position: absolute`로 검색창 오른쪽에 오버레이, 검색창
  자체(.search-bar)만 그리드 중앙 열에 둬서 수학적으로 정중앙에 오도록 함
- 결과: 검색창은 정중앙에 왔지만, 검색어가 길거나 로그인 상태(nav 링크+긴 이름)일 때 티커가
  `.site-header__right`(로그인 버튼/nav) 위로 겹침
- 사용자 피드백: "티커가 로그인 버튼 침범하는데 이걸 푸시하겠다고?" → 반려, 푸시 시도 중단

## Attempt 3 — 2026-08-19 ✅ 최종 적용 (커밋 3df5360)
- 시도:
  1. 티커의 고정폭 "슬롯" 개념을 완전히 제거(임의의 CSS 고정폭 예약 없음)
  2. 대신 `js/header-search.js`에서 검색어를 10자로 자르고 "..." 붙임(`truncateKeyword`,
     `TICKER_KEYWORD_MAX_LENGTH = 10`) — 티커가 가질 수 있는 최대 너비 자체를 좁은 범위로 제한
  3. 티커는 `flex: none; max-width: 150px`로 내용 길이만큼만 자연스럽게 shrink-to-fit
  4. `.site-header__inner`를 3열 그리드(로고 1fr / 검색창+티커 minmax(240px,520px) / nav+auth 1fr)로
     바꿔, 검색창+티커 묶음 전체가 헤더 정중앙에 오도록 함(로고와 우측 영역 너비가 달라도 영향 없음)
  5. 로그인/회원가입 버튼 2개를 `/login.html`로 이동하는 버튼 1개("로그인/회원가입")로 통합
     (로그인 페이지 하단에 이미 회원가입 링크가 있어 별도 버튼 불필요)
- 결과: 로컬 정적 서버(PowerShell HttpListener, 8910 포트)와 실제 프로덕션 페이지에 최종
  CSS/JS/HTML을 주입해 `getBoundingClientRect()`로 실측, 모두 통과
- 증거(레이아웃 실측, 1280px 데스크탑):
  - 검색창+티커 묶음 중앙 632.5px = 헤더 전체 중앙 632.5px (정확히 일치)
  - 비로그인 상태, 최악의 티커(10자+"...", 실측 142px)에도 티커 우측 892.5px vs
    로그인 버튼 시작 1083.9px → 191px 여유, 겹침 없음
  - 로그인 상태(판매자, SELLER nav 링크 노출 + 긴 이름 "전용운판매자님") 시뮬레이션에도
    692.5px 우측 끝 vs 908.5px → 16px 여유로 타이트하지만 겹침 없음
  - 짧은 검색어("귤")일 때 티커 실측 50px로 자연스럽게 줄어듦(빈 공간 없음 확인)
- 커밋: fd5bd5c(실검 티커 흔들림 1차 수정 + 그리드 중앙 정렬 + 로그인 버튼 통합),
  48a4f69(검색창만 중앙 정렬 시도, Attempt 2에서 반려됨), 3df5360(최종)
