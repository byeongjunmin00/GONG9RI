# 브랜치 가이드 (branch-guide)

이 저장소의 git 브랜치 규칙이다.

> `basic-harness` 템플릿 원본은 `master`(보호) → `dev`(통합) → `feature/*` 3단 구조인데,
> GONG9RI는 2인 팀이라 **브랜치 분기 없이 `main`에 바로 커밋**하는 방식으로 단순화했다.
> 팀 규모가 커지거나 배포 파이프라인이 생기면 그때 `feature/*` + PR 흐름을 다시 도입하는 걸 고려한다.

## 브랜치 모델

```
main   ← 유일한 브랜치. 모든 작업을 여기서 바로 진행
```

## 작업 흐름

```
1. main에서 바로 작업 (Plan → Generate → Evaluate)
2. 완료 → 커밋 (PR 없이 main에 직접)
3. 작업 시작 전 최신 main을 pull해서 충돌을 최소화한다 (2인이 같은 파일을 건드릴 수 있음)
```

## 충돌 시

- 같은 파일을 각자 작업해서 충돌 나면, `git pull` 후 conflict 마커를 직접 해결하고 병합 커밋으로 마무리한다.
- 병합 커밋 메시지는 git 기본 메시지(`Merge branch 'main' of ...`)를 그대로 쓴다 (별도 컨벤션 없음).
