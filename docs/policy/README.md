# policy — 정책 (비즈니스 규칙)

여러 기능이 **공유하는 비즈니스 규칙**을 담는 폴더다.
정책은 특정 기능에 종속되지 않는 **진실의 원천(SSOT)**이며, 각 기능의 `design.md`가 이걸 **참조**한다.

## 왜 따로 두나

정책은 여러 기능/개념에 걸쳐 적용된다. 예를 들어 "공구팀 성사/미성사 판정 정책"은
`team/join`, `team/deadline-check`, `payment/refund` 등 여러 곳에서 지켜야 한다.
이걸 각 `design.md`에 복붙하면 어긋나므로(드리프트), **한 곳(정책 문서)에 두고 참조**한다.

- **정책(policy)** = 무엇이 규칙인가 (비즈니스가 정함). 예: 성사 판정 기준, 환불 트리거 시점.
- **design.md** = 그 규칙을 어떻게 구현하는가 (정책을 참조).
- 정책과 design이 어긋나면 → **정책이 상위 진실**이다.

## 구조 & 이름

```
docs/policy/
├── README.md               ← (이 문서)
└── {정책이름}.md            예: team-success-criteria.md, refund-trigger.md
```

## 정책 문서 템플릿

```markdown
# {정책명}

## 규칙
<!-- 무엇이 정해져 있는가 (조건·한계·예외) -->

## 근거 / 배경
<!-- 왜 이 규칙인가 -->

## 적용 대상
<!-- 이 정책을 참조하는 기능들: team/join, payment/refund 등 -->
```

## design.md에서 참조하는 법

`design.md`의 "관련 정책·의존" 항목에 정책 문서를 링크한다.

```markdown
## 관련 정책·의존
- docs/policy/team-success-criteria.md (공구팀 성사 판정 기준)
```

> 정책이 바뀌면 정책 문서를 고치고, 그 정책을 참조하는 기능들의 영향 여부를 검토한다.
