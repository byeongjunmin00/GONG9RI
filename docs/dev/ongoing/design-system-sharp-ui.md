# 디자인 시스템 각진 UI + 여백/그리드 조정 (2단계, 무신사 톤 참고)

대상: frontend/design-system     <!-- 완료 시 docs/dev/frontend/design-system/changes/로 이동 -->
담당: 전용운

## 배경 / 요구

1단계(`docs/dev/frontend/design-system/changes/002-showcase-rebrand.md`)에서 색상/폰트/로고를 무신사 톤으로 바꿨다. 이번엔 사용자가 실제 무신사 화면 스크린샷(본인 브라우저로 찍은 것) 2장을 보여주며 아래를 요청했다 — **이번엔 "레이아웃은 안 바꾼다"는 이전 제약을 명시적으로 취소**하고, 아래 항목들에 한해 레이아웃(`css/layout.css`)도 함께 바꾸기로 했다.

1. **버튼이 너무 둥글다** ("AI 냄새 난다") — `border-radius`를 줄여 더 각지게.
2. **상품 카드도 무신사처럼 더 촘촘하고 각지게** — 카드 모서리 `border-radius` 축소 + 그리드 카드 간 간격(`grid-cards` gap) 좁힘. 스크린샷은 참고용(UX 패턴/밀도만 참고, 무신사의 실제 상품 이미지·브랜드명·문구는 절대 가져오지 않는다).
3. **페이지 좌우 여백**을 무신사처럼 두고 싶다 — 컨테이너(`--container-max`)/좌우 패딩 조정.
4. **검색 입력창도 너무 둥글다** — `border-radius` 축소.
5. **헤더 검색 버튼 클릭 시 상단에 넓은 팝업 패널**이 뜨는 UI — 사용자가 준 무신사 검색 팝업 스크린샷 참고. **단, 이번엔 입력칸 모양(팝업 셸 + 열고 닫는 동작)만 만든다.** "최근 검색어"/"최근 방문한 브�랜드"/"인기·급상승 검색어" 같은 콘텐츠 섹션은 넣지 않는다 — GONG9RI엔 브랜드 개념도 없고 검색 통계 백엔드도 없어서, 가짜 데이터를 넣으면 사용자를 속이는 셈이 된다(사용자 확인 완료, "팝업 입력칸 모양만" 선택).

## 저작권 제약 (변하지 않음)

무신사 스크린샷에 나온 실제 상품 이미지·브랜드명·상품명·검색어·문구를 그대로 가져오지 않는다. 참고하는 건 오직 **구조적 패턴**(그리드 밀도, 모서리 각짐 정도, 팝업이 뜨는 위치/형태)뿐이다.

## 이번 범위

이전 1단계와 동일하게 **`design-system.html` 쇼케이스 페이지 기준**으로 작업한다(메인/상세 페이지 실제 반영은 여전히 후속 계획). 다만 아래 항목은 전역 CSS라 모든 페이지에 자동 반영된다:

- `css/tokens.css` — `--radius-sm`/`--radius-md`/`--radius-lg`(현재 8/16/24px) 값을 축소해 더 각진 인상으로(정확한 px는 Generate가 정함, 예: 4/8/12px 근처). `--container-max`(현재 1200px)나 컨테이너 좌우 패딩 값 조정.
- `css/layout.css` — **이번엔 명시적으로 허용됨.** `.grid-cards`의 `gap` 값 축소(더 촘촘하게), `.container`의 좌우 padding 조정. 그 외 구조(컬럼 수, 브레이크포인트, 헤더/푸터 단수 등)는 이번 요청 범위가 아니므로 안 건드린다.
- `css/components.css` — 검색 입력창(`.search-input*`) `border-radius` 축소. 새로 만들 검색 팝업 패널 스타일 신설.
- `partials/header.html` — 검색 버튼을 추가해야 팝업을 열 수 있다(현재 헤더엔 검색 버튼 자체가 없음 — 1단계에서 검색 UI는 쇼케이스 컴포넌트로만 만들고 헤더엔 안 넣었었다). 검색 아이콘 버튼 + 팝업 패널 마크업 추가. `header-auth.js`가 참조하는 기존 id/속성은 그대로 유지.
- **신규**: `js/` 아래 검색 팝업 열고 닫는 스크립트 추가(새 파일, 예: `js/search-popup.js`) 또는 기존 `js/include.js` 흐름에 맞춰 작은 스크립트 추가 — Generate가 기존 컨벤션(`js/chat-widget.js` 패턴 등)을 참고해 정한다. **제출/검색 실행 로직은 넣지 않는다**, 열기/닫기 토글만.

## 하지 않는 것

- 검색 팝업에 "최근 검색어"/"최근 방문한 브랜드"/"인기 검색어"/"급상승 검색어" 등 콘텐츠 섹션을 넣지 않는다 — 백엔드 없음, 가짜 데이터 금지.
- 검색 제출·실제 필터링 기능 구현 안 함(백엔드 API 여전히 없음).
- 그리드 컬럼 수, 브레이크포인트, 헤더/푸터 단수 구조는 안 건드린다(이번 요청은 간격/모서리/여백/팝업 셸만).
- 무신사 스크린샷의 실제 콘텐츠(상품·브랜드·검색어) 복사 안 함.
- 색상 토큰(1단계에서 이미 확정된 다크 세이지 팔레트) 재변경 안 함.
- 상태 뱃지 색상, 백엔드 변경 없음.

## 평가(통과) 기준

- `./gradlew test` 통과.
- 버튼/카드/검색창 모서리가 눈에 띄게 각져 보이는가(라운드 대폭 축소).
- 상품 카드 그리드 간격이 좁아져 더 촘촘한 밀도로 보이는가.
- 페이지 좌우 여백이 조정됐는가(다른 페이지에서도 자연스럽게 반영, 콘텐츠 폭 안 깨짐).
- 헤더 검색 버튼 클릭 시 상단에 팝업 패널이 열리고, 다시 누르거나 닫기 조작 시 닫히는가. 입력칸 외 콘텐츠(최근검색어 등)가 없는가.
- 팝업엔 제출 기능이 없고 눌러도 검색이 실행되지 않는가(의도된 동작).
- 기존 페이지 레이아웃이 grid/컨테이너 조정 후 시각적으로 깨지지 않는가.
- 브라우저 콘솔 에러 없음.

## 리스크

- 그리드 gap/컨테이너 패딩은 전역이라 메인 페이지 등에도 즉시 반영됨 — 회귀 확인 필요.
- radius 토큰 축소가 여러 컴포넌트(버튼/카드/뱃지/폼/모달 등)에 광범위하게 영향을 줄 수 있어, 의도치 않게 너무 각져 보이는 요소가 생길 수 있음.
- 검색 팝업은 이번에 처음 JS가 추가되는 부분이라(1단계는 JS 무변경이었음) `include.js`의 헤더 삽입 타이밍과 맞물려 이벤트 바인딩 순서에 유의해야 한다.
