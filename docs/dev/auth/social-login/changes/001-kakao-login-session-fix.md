# 카카오 로그인 역할 불일치 안내 + 로그아웃 세션 정리 강화

대상: auth/social-login (주), auth/logout (부)
담당: 전용운

## 배경 / 요구

1. 이미 카카오로 SELLER 가입된 계정이 "카카오로 구매자 가입" 버튼을 눌러도 안내 없이 조용히
   기존 role(SELLER)로 로그인됨. `MemberService.findOrCreateByKakao()`가 기존 회원이면
   `intendedRole`을 완전히 무시하고 그대로 반환하기 때문 — 원래는 "재로그인 시 role이 바뀌는 걸
   막기 위한" 의도된 설계였으나(`docs/dev/auth/social-login/design.md` 참고), 안내 부재는
   고려되지 않았음.
2. 로그아웃 후 재로그인 시 인증 없이 로그인되는 것처럼 보임. `AuthController.logout()`이
   `session.invalidate()`만 하고 `SecurityContextHolder.clearContext()`/쿠키 만료를 하지 않으며,
   `SecurityConfig`에 표준 `.logout(...)` 설정이 없음.

사용자 확정 사항:
- 역할 불일치 시 로그인은 그대로 시키되(기존 role 유지), "이미 O로 가입되어 있어 O로
  로그인되었습니다" 안내를 화면에 반드시 보여준다.
- signup.html 카카오 버튼 문구: "카카오로 구매자 가입"/"카카오로 판매자 가입" →
  "카카오로 구매자 시작하기"/"카카오로 판매자 시작하기"로 변경.
- 로그아웃은 세션+시큐리티컨텍스트+쿠키를 확실히 정리한다.

스코프 제외(별도 작업): 액세스 토큰 null 미검증, 동시 요청 경쟁 상태, 코드 중복, OAuth 계정
테이블 분리, 404 핸들러 로그 누락, 매직 스트링, 결제 테스트 커버리지 갭, 카카오 임시 비밀번호
해싱 비용 — 전부 이번 스코프 밖.

## 설계

### A. 역할 불일치 안내 (auth/social-login)
- `findOrCreateByKakao()`가 "기존 회원 + role 불일치" 여부를 호출부가 판별할 수 있게 결과를
  돌려주는 방향으로 바꾼다(정확한 반환 형태는 Generate가 결정).
- `kakaoCallback()`은 이 판별 결과로, 로그인은 그대로 진행하되 성공 리다이렉트에 안내 신호를
  함께 전달한다 — 기존 `login.html`의 `?signup=success`/`?error=kakao` 같은
  "쿼리파라미터+배너" 패턴 재사용 방향(정확한 파라미터명·표시 위치는 Generate가 결정).
- role이 일치하거나, role 파라미터 없는 일반 "카카오로 로그인" 버튼 경로는 현행 유지(안내 없음).

### B. 카카오 버튼 문구 변경 (frontend)
- `signup.html` 두 버튼 문구를 "카카오로 구매자/판매자 시작하기"로 변경.

### C. 로그아웃 정리 강화 (auth/logout)
- 세션 무효화에 더해 `SecurityContextHolder.clearContext()`, 인증 쿠키 만료까지 확실히
  수행하도록 한다 — 표준 로그아웃 핸들러 체인 활용 여부는 Generate가 결정.
- 조사 중 "브라우저 뒤로가기 캐시(bfcache)로 로그아웃 전 화면이 그대로 보이는" 가능성도
  배제 못 함을 확인 — 인증 필요 페이지 응답에 캐시 방지 헤더 추가도 이번 스코프에 포함.

### D. 진단성 개선 (리뷰 1·2번 반영)
- 카카오 로그인 실패 로그가 스택트레이스 없이 메시지만 남기는 문제 수정.
- 카카오 합성 username(`kakao_{id}`)이 일반 회원가입과 충돌할 수 있는데 사전 검증이 없는
  문제 수정 — `signup()`의 기존 `existsByUsername` 패턴과 동일하게.

## 평가(통과) 기준
- 기존 회귀 테스트 전체 통과, 특히 `kakaoCallback_existingAccount_ignoresIntendedRole`은
  "role은 유지되지만 안내 신호가 전달된다"로 갱신
- 신규 테스트: 로그아웃 후 같은 세션/쿠키로 인증 필요 API 재호출 시 401 확인
- 신규 테스트: 카카오 신규 가입 시 합성 username이 기존 일반 가입 아이디와 충돌하면 명확한
  에러 반환 확인
- `./gradlew test` 전체 통과
- 실제 화면에서 (a) 판매자 계정으로 "구매자로 시작하기" 클릭 시 안내 문구 노출, (b) 로그아웃
  후 재로그인 흐름에서 인증 없이 통과되지 않는지 수동 확인

## 리스크/전제
- 로컬 MySQL 가동 필요. 카카오 실제 브라우저 흐름까지 재현하려면 로컬 카카오 앱 설정 필요
  (없으면 Mockito 기반 통합 테스트로만 검증)
- 안내 신호를 프론트로 전달하는 방식은 로그인 성공 리다이렉트 대상이 `/`(메인 페이지)라
  기존 `login.html`의 배너 로직을 그대로 못 쓸 수 있음 — 메인 페이지에 새로 추가할지
  `login.html`을 경유시킬지는 Generate 단계에서 결정
- bfcache 대응(캐시 방지 헤더)은 정적 리소스 서빙 방식에 따라 적용 범위가 제한될 수 있음
