# 세션 만료 후 로그아웃 버튼이 먹통이던 버그 수정

대상: auth/me
담당: 민병준

## 배경 — 사용자 리포트

> "이거 이렇게 시간 좀 오래 지나면 로그아웃 눌러도 로그아웃이 안 되는데 버그인가?"

페이지를 오래 열어둔 뒤 로그아웃 버튼을 누르면 **화면에 아무 일도 일어나지 않는다.**

## 원인

체인 전체를 확인했다.

1. `POST /api/auth/logout`이 `SecurityConfig`의 permitAll 목록에 **없다** → `anyRequest().authenticated()`에 걸려 **유효한 세션을 요구**한다.
2. 세션 타임아웃 설정이 없어 **톰캣 기본값 30분**.
3. 30분 방치하면 서버 세션이 만료되지만, **화면은 페이지 로드 시점에 그린 로그인 헤더 그대로**다(`/auth/me`가 그때는 성공했으므로).
4. 로그아웃 클릭 → `POST /api/auth/logout` → **401**.
5. `api.js`는 `!res.ok`에서 예외를 던지고, `header-auth.js`의 `.catch`는 **`console.error`만** 하고 끝났다.
6. → 사용자에겐 버튼이 먹통으로 보인다.

**주목할 점**: `AuthController.logout()`은 이미 세션이 없어도 안전하게 동작하도록 짜여 있었다.

```java
HttpSession session = httpRequest.getSession(false);
if (session != null) { session.invalidate(); }   // null이어도 문제없음
```

즉 **컨트롤러는 멱등하게 작성돼 있는데 인가 설정이 그 경로에 도달조차 못 하게 막고 있었다.** 설정이 코드의 의도를 배신한 형태다.

## 변경

**백엔드** — `POST /api/auth/logout`을 permitAll로. 로그아웃은 "이미 로그아웃된 상태"에서 호출돼도 성공해야 하는 멱등 연산이다. 인증을 요구할 이유가 없다(세션이 없으면 지울 것도 없고, 남의 세션을 지울 수도 없다 — 자기 쿠키만 만료시킨다).

**프론트엔드** — 성공/실패와 무관하게 새로고침한다.

```js
window.Api.post('/auth/logout')
  .catch(logError)      // 실패해도 삼키고
  .then(reload);        // 항상 새로고침
```

로그아웃은 "서버 상태와 화면을 다시 맞추는" 동작이라, 실패했을 때 아무것도 안 하면 화면이 낡은 채 남는 게 최악이다. 세션이 이미 만료됐다면 사용자는 사실상 이미 로그아웃된 것이므로 새로고침하면 헤더가 비로그인 상태로 정상 복귀한다.

## 검증

- `logout_withoutSession_isStillSuccessful` — 세션 없이 호출해도 204
- `logout_calledTwice_isIdempotent` — 연속 두 번 호출해도 두 번 다 204
- **수정을 되돌리면 두 테스트가 실제로 실패하는 것까지 확인**했다

### 기존 테스트를 교체했다

`logout_unauthorized`(같은 요청에 401/`UNAUTHORIZED`를 기대하던 테스트)를 삭제했다. **그 기대값 자체가 이 버그를 고정하고 있었기 때문**이다 — 동작을 의도적으로 바꾸면서 함께 교체했고, 새 테스트 주석에 무엇을 대체했는지 명시했다.

> 테스트를 새 동작에 맞춰 고치는 건 회귀를 숨길 수 있어 조심해야 하는 일이라, "왜 기대값이 바뀌었는지"를 코드와 문서 양쪽에 남겼다.

## 배운 것

**컨트롤러가 방어적으로 짜여 있어도 인가 설정이 그 경로를 막고 있으면 의미가 없다.** 이 코드는 세션이 없는 경우를 명시적으로 처리하고 있었는데, 정작 그 분기는 한 번도 실행될 수 없었다. 방어 코드를 넣을 때는 "이 경로에 실제로 도달할 수 있는가"까지 확인해야 한다.

그리고 **실패 경로에서 `console.error`만 하는 건 사용자 입장에선 아무 일도 안 한 것과 같다.** 사용자가 누른 버튼은 어떤 결과든 화면에 반영돼야 한다.
