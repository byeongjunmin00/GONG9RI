# 모바일 화면 수정 (frontend/mobile-fixes) — Design

## 개요

데스크톱에서만 확인하고 넘어간 UI가 좁은 화면에서 깨지는 것들을 모은다. 두 건 다 **실제 휴대폰으로 써 본 사용자가 발견**했다 — 데스크톱 브라우저를 좁혀보는 것만으로는 드러나지 않는 종류였다.

## 1) 상품 상세 썸네일이 모바일에서 계속 따라 내려옴

`.product-detail-media`에 `position: sticky`가 걸려 있는데, 모바일(≤991px)에서는 그리드가 1열로 바뀌어 사진이 구매 옵션 **위에** 쌓인다. 이 배치에서 sticky는 의미가 없다 — "왼쪽 사진을 보면서 오른쪽 옵션을 읽는" 2열 배치를 위한 것이기 때문이다. 남겨두면 스크롤할 때 사진과 카카오톡 공유 버튼이 아래 내용을 계속 덮는다.

→ 1열 구간에서 `position: static`으로 되돌린다.

**규칙 순서가 중요하다.** 미디어쿼리와 기본 규칙은 명시도가 같아서 **뒤에 오는 쪽이 이긴다.** 처음엔 미디어쿼리를 기본 규칙보다 위에 뒀다가, 그러면 `sticky`가 다시 덮어써 수정이 무효가 되는 걸 발견해 순서를 바꿨다.

> 데스크톱에서 겪은 겹침(`product/detail-ui-redesign/changes/003`)은 그리드 구조 자체를 고쳐 해결했지만, 모바일은 **애초에 고정할 이유가 없어서** 끄는 게 맞다 — 원인이 다르므로 해법도 다르다.

## 2) 모바일에서 알림 패널이 화면 밖으로 잘림

알림 패널은 벨(`.site-header__notifications`, `position: relative`) 기준으로 `right: 0`에 붙어 **왼쪽으로 320px 뻗는다.** 벨이 화면 오른쪽에 있는 모바일에서는 그 320px이 화면 왼쪽 밖으로 넘어가 잘린다.

**기존에도 모바일 대응이 있었지만 효과가 없었다.**

```css
@media (max-width: 420px) {
  .header-notifications-panel { width: min(320px, 90vw); }
}
```

390px 화면에서 `90vw = 351px`이라 `min()`이 **320px을 그대로 고른다** — 아무것도 줄어들지 않았다. 그리고 애초에 잘림의 원인은 폭이 아니라 **어디에 붙느냐**였다.

→ 좁은 화면(≤767px, 헤더가 모바일 레이아웃으로 바뀌는 지점)에서는 벨의 `position: relative`를 풀어, 패널이 그 위의 `.site-header`(sticky = 위치가 지정된 요소)를 기준으로 잡히게 하고 좌우를 여백만 남기고 벌린다. 헤더는 화면 전체 폭이라 어떤 기기에서도 화면 안에 들어온다.

긴 알림 문구가 패널 폭을 밀어내지 않도록 `overflow-wrap`도 함께 걸었다.

## 배운 것

**"모바일 대응 규칙이 있다"와 "그 규칙이 실제로 동작한다"는 다르다.** `min(320px, 90vw)`는 언뜻 안전해 보이지만 대상 화면 크기를 넣어보면 아무 일도 하지 않는다. 그리고 이 경우엔 조건을 고쳐도 소용없었다 — 문제의 축이 폭이 아니라 기준점이었기 때문이다.
