# 모바일 화면 수정 (frontend/mobile-fixes) — Design

## 개요

데스크톱에서만 확인하고 넘어간 UI가 좁은 화면에서 깨지는 것들을 모은다. 두 건 다 **실제 휴대폰으로 써 본 사용자가 발견**했다 — 데스크톱 브라우저를 좁혀보는 것만으로는 드러나지 않는 종류였다.

## 1) 상품 상세 썸네일이 모바일에서 계속 따라 내려옴

`.product-detail-media`에 `position: sticky`가 걸려 있는데, 모바일(≤991px)에서는 그리드가 1열로 바뀌어 사진이 구매 옵션 **위에** 쌓인다. 이 배치에서 sticky는 의미가 없다 — "왼쪽 사진을 보면서 오른쪽 옵션을 읽는" 2열 배치를 위한 것이기 때문이다. 남겨두면 스크롤할 때 사진과 카카오톡 공유 버튼이 아래 내용을 계속 덮는다.

→ 1열 구간에서 `position: static`으로 되돌린다.

**규칙 순서가 중요하다.** 미디어쿼리와 기본 규칙은 명시도가 같아서 **뒤에 오는 쪽이 이긴다.** 처음엔 미디어쿼리를 기본 규칙보다 위에 뒀다가, 그러면 `sticky`가 다시 덮어써 수정이 무효가 되는 걸 발견해 순서를 바꿨다.

> 데스크톱에서 겪은 겹침(`product/detail-ui-redesign/changes/003`)은 그리드 구조 자체를 고쳐 해결했지만, 모바일은 **애초에 고정할 이유가 없어서** 끄는 게 맞다 — 원인이 다르므로 해법도 다르다.

## 2) 모바일에서 알림 패널이 화면 밖으로 잘림

알림 패널은 벨(`.site-header__notifications`, `position: relative`) 기준으로 `right: 0`에 붙어 **왼쪽으로 320px 뻗는다.** 벨이 화면 오른쪽에 있는 모바일에서는 그 320px이 화면 왼쪽 밖으로 넘어가 잘린다.

**기존에도 모바일 대응이 있었지만 효과가 없었다.**

```css
@media (max-width: 420px) {
  .header-notifications-panel { width: min(320px, 90vw); }
}
```

390px 화면에서 `90vw = 351px`이라 `min()`이 **320px을 그대로 고른다** — 아무것도 줄어들지 않았다. 그리고 애초에 잘림의 원인은 폭이 아니라 **어디에 붙느냐**였다.

→ 좁은 화면(≤767px, 헤더가 모바일 레이아웃으로 바뀌는 지점)에서는 벨의 `position: relative`를 풀어, 패널이 그 위의 `.site-header`(sticky = 위치가 지정된 요소)를 기준으로 잡히게 하고 좌우를 여백만 남기고 벌린다. 헤더는 화면 전체 폭이라 어떤 기기에서도 화면 안에 들어온다.

긴 알림 문구가 패널 폭을 밀어내지 않도록 `overflow-wrap`도 함께 걸었다.

## 배운 것

**"모바일 대응 규칙이 있다"와 "그 규칙이 실제로 동작한다"는 다르다.** `min(320px, 90vw)`는 언뜻 안전해 보이지만 대상 화면 크기를 넣어보면 아무 일도 하지 않는다. 그리고 이 경우엔 조건을 고쳐도 소용없었다 — 문제의 축이 폭이 아니라 기준점이었기 때문이다.

## 3) 헤더 모바일 배치 순서 — order가 서로 다른 flex 컨테이너에 걸쳐 있으면 무관하게 작동한다

`.site-header__inner`(로고 / 검색창 / `.site-header__right`)에서 검색창에만 `order: 3`을 줘서 맨 뒤로 보내려 했는데, `.site-header__nav`도 `order: 3`을 갖고 있어 "검색창 다음에 nav가 온다"고 착각하기 쉽다. 실제로는 nav가 검색창과 다른 flex 컨테이너(`.site-header__right`) 소속이라 두 `order:3`은 서로 무관하게 작동했고, 결과적으로 렌더링 순서는 "로고 → (nav+알림+로그인 묶음) → 검색창(맨 아래)"이 됐다 — 핵심 기능인 검색이 오히려 제일 아래로 밀리는, 의도와 다른 배치였다.

→ 로고(`order:1`) / 검색창(`order:2`) / `.site-header__right`(`order:3`, 신규 명시)로 **최상위 3개 형제에만** order를 명시적으로 준다. nav 내부의 `order:3`(알림·로그인보다 아래로)은 그대로 유지 — 이건 `.site-header__right` 안에서만 의미 있는 별개의 서브 순서다.

> **배운 것**: `order`는 "형제 사이의 순서"이지 "페이지 전체의 순서"가 아니다. 같은 order 값이라도 부모(flex 컨테이너)가 다르면 서로 아무 관계가 없다 — 값만 보고 순서를 유추하면 이번처럼 틀린다.

## 4) 헤더 모바일 컨트롤 높이 불일치 + hover 스타일의 터치 sticky-hover

모바일에서 알림벨·찜 아이콘(32px 원형)과 로그인/로그아웃 버튼(`btn-sm`, padding 8px + 12px 폰트로 실측 28~30px)이 같은 줄에 나란히 놓이면 높이 차이가 또렷하게 보였다(사용자가 실기기에서 직접 발견). → 모바일(`≤767px`)에서 아이콘을 40px로, 버튼에 `min-height:40px`을 줘서 맞췄다. 겸사겸사 터치 타겟도 (32px→40px로) 개선됐다. 카드 위 찜 버튼(`.card-wishlist-btn`)도 같은 이유로 모바일에서 32→36px(카드 안이라 헤더보다는 작게).

또한 `.card:hover`/`.btn-primary:hover`/`.btn-secondary:hover`/`.card-wishlist-btn:hover`의 리프트(transform)·그림자 효과에 `@media (hover: hover)` 가드가 전혀 없었다 — 터치 기기는 탭을 hover로 흉내 내는 경우가 있어, 가드 없이 두면 카드를 탭한 뒤 다음 탭 전까지 리프트 효과가 "붙어 있는" 상태로 남을 수 있다(상품 카드처럼 여러 개를 계속 탭하는 화면에서 특히 거슬리는 유형). → 위 hover 규칙을 `@media (hover: hover)` 안으로 옮겨, 실제 hover 가능한 입력 장치(마우스 등)에서만 적용되게 했다. 변형이 없는 `.btn-ghost:hover`(색상만 변경)는 sticky 되어도 거슬림이 적어 범위에서 제외했다.

카드 2열 모바일 그리드(카드 폭 ~165px)에서 판매자명·가격·진행률 텍스트가 겹치거나 줄바꿈될 우려가 있어 실측했으나, 실제 콘텐츠 길이(판매자명 9자+신뢰배지, 5자리 가격 2종)로는 `.card-title`의 의도된 말줄임(ellipsis) 외에 줄바꿈·겹침이 없어 추가 조정은 하지 않았다.
