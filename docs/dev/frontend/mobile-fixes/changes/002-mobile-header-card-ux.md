# 모바일 헤더/카드 UX 정리

대상: frontend/mobile-fixes
담당: 전용운

## 배경 / 요구

사용자가 모바일 화면에서 직접 확인하고 "어색하다"고 지적한 항목들:
- 헤더 로그인 버튼 높이가 다른 요소와 안 맞음
- 상품 카드 등 여러 곳이 모바일에서 UX가 좋지 않음

코드(`css/layout.css`, `css/components.css`, `partials/header.html`)를 읽어 원인을 특정했다. 실기기/실브라우저로 아직 육안 확인은 못 했고(로컬에 Redis 없이는 상품 목록·상세가 500이 나서 확인 자체가 안 됨 — `AGENTS.md` 참고), 아래는 CSS 수치·구조를 근거로 한 분석이다. Docker는 이 환경에 설치돼 있어 Generate 이후 `docker compose up -d` + `bootRun`으로 실제 렌더링 검증이 가능하다.

## 원인 분석

### 1) 헤더 로그인 버튼 높이 불일치

헤더 한 줄에 같이 놓이는 컨트롤들의 실제 높이가 제각각이다:
- 검색창(`.search-bar`): 내부 버튼 40px + 여백 → 약 48px
- 알림벨(`.site-header__notifications-bell`) / 찜 아이콘(`.site-header__wishlist-link`): 32×32px 원형 고정
- 로그인 버튼(`.btn.btn-sm`, `.btn-primary`): `padding: 8px 16px` + `font-size: 12px` + `line-height: 1` → 약 28~30px

즉 버튼 자체가 다른 헤더 컨트롤보다 CSS 수치상 뚜렷하게 낮다. 데스크톱에서는 한 줄에 여유 공간이 많아 덜 티 나지만, 모바일에서는 이 요소들이 좁은 폭에 붙어서 나란히 배치되기 때문에 높이 차이가 바로 눈에 띈다.

### 2) 모바일에서 헤더 배치 순서 자체가 어색함

`layout.css`의 `@media (max-width: 767px)` 규칙을 구조적으로 보면:
- `.site-header__inner`(로고 / 검색창 / `.site-header__right` 3개를 담는 최상위 flex)에서 `.site-header__search`에 `order: 3`을 줘서 검색창을 맨 뒤로 보낸다.
- 그런데 `.site-header__nav`의 `order: 3`은 검색창과 **같은 flex 컨테이너 소속이 아니다** — nav는 `.site-header__right` 내부(알림벨·로그인 버튼과 같은 부모) 자식이라, 이 order는 검색창과 무관하게 그 안에서만 순서를 정한다.
- 결과적으로 모바일 렌더링 순서는 "로고 → (nav+알림벨+로그인버튼 묶음) → 검색창(맨 아래, 전체폭)"이 된다. 검색이 페이지 최상단 핵심 기능인데 정작 화면 맨 아래로 밀려나는 배치다. 처음에 이렇게 순서를 준 의도(검색창을 아래로 보내기)와 실제 결과(nav/버튼 묶음보다도 더 아래로 밀림)가 어긋난 것으로 보인다.
- 또한 `.site-header__right`는 여전히 `display:flex; flex-wrap:wrap`이라 그 안에서 알림벨+로그인 버튼(첫 줄) 밑에 nav 링크(`width:100%`로 강제 줄바꿈, 둘째 줄)가 오는 별도의 서브 레이아웃이 생긴다 — 헤더 안에 레이아웃이 두 겹으로 겹쳐 있는 구조라 예측하기 어렵고, 위 1)의 높이 불일치가 가장 먼저 눈에 띄는 지점도 바로 이 알림벨+로그인 버튼 첫 줄이다.

### 3) 상품 카드류 모바일 UX

- `.card:hover`(카드 전체 `translateY(-8px) scale(1.015)`), `.btn-primary:hover`(`translateY(-2px)`), `.card-wishlist-btn:hover`(`scale`) 등 hover 전용 스타일에 `@media (hover: hover)` 같은 가드가 전혀 없다. 터치 기기는 마우스 hover가 없는 대신 탭을 hover로 흉내 내는 브라우저가 많아, 카드를 탭하면 리프트/그림자 효과가 다음 탭 전까지 그대로 "붙어 있는" 현상(sticky hover)이 날 수 있다. 상품 카드처럼 화면에 여러 개가 촘촘히 있고 계속 탭하며 넘기는 UI에서는 특히 거슬리는 유형의 버그다.
- `.grid-cards`는 모바일에서 2열 고정(`repeat(2, 1fr)`, gap 12px)이라 카드 폭이 좁다. 그 안에서 `.card-price-row`(할인 전/후 가격), `.card-seller-row`(판매자명 + 신뢰 배지), `.card-progress`(진행률 라벨+퍼센트) 등 텍스트 요소가 한 줄에 여러 개 붙는 구성이라, 좁은 폭에서 줄바꿈·겹침·잘림 여지가 있다 — 다만 이건 실제 데이터(가격 자릿수, 판매자명 길이)에 따라 갈리므로 실기기 확인이 필요한 항목이다.
- `.card-wishlist-btn` 등 카드 위 찜 버튼이 32×32px로, 일반적인 모바일 터치 타겟 권장 크기(약 44px)보다 작다.

## 설계 (접근 방향)

1. **헤더 컨트롤 높이 통일**: 검색창/알림벨/찜 아이콘/로그인·로그아웃 버튼이 모바일 헤더의 같은 줄에 놓일 때 시각적으로 동일한 기준 높이에 맞춰지도록 조정하는 방향. 로그인 버튼 쪽을 다른 아이콘 컨트롤 높이에 맞춰 키우는 쪽이 자연스러워 보인다(작은 텍스트 버튼을 원형 아이콘 크기로 줄이는 것보다).
2. **모바일 헤더 순서 재구성**: "로고 → 검색창 → (필요시) nav/알림/로그인" 같이 실제 의도한 우선순위와 렌더링 순서가 일치하도록 flex 순서 구조를 다시 짠다. 지금처럼 서로 다른 flex 컨테이너에 걸쳐 있는 `order` 값들이 의도와 다르게 상호작용하지 않도록, 순서 제어를 한 군데(가급적 최상위 컨테이너)로 모으는 방향을 우선 검토한다.
3. **터치 sticky-hover 방지**: 카드·버튼류의 hover 전용 스타일(리프트/그림자/스케일)을 hover가 실제로 가능한 입력 장치에서만 적용되도록 조건을 건다.
4. **카드 밀집도·터치 타겟 재검토**: 2열 모바일 카드 안 텍스트 요소 간격/줄바꿈 여지를 실기기 확인 후 필요한 곳만 조정한다. 찜 버튼 등 인터랙티브 아이콘의 터치 타겟을 모바일 기준으로 키우는 것을 검토한다.

카드 컬럼 수(2열)나 브랜드 톤(그라디언트·라운드 등 디자인 시스템)은 이번 범위에서 바꾸지 않는다 — 지적된 것은 배치/상호작용 문제이지 톤앤매너 문제가 아니다.

## 태스크
- [ ] 헤더 모바일 컨트롤 높이 통일 (로그인/로그아웃 버튼 ↔ 검색바/알림벨/찜 아이콘)
- [ ] 헤더 모바일 순서 구조 재정리 (검색창이 nav/auth 묶음보다 먼저 오도록)
- [ ] hover 전용 스타일에 터치 기기 sticky-hover 방지 조건 적용 (카드, 주요 버튼)
- [ ] 상품 카드 2열 모바일 레이아웃 실기기 확인 후 밀집 구간(가격/판매자행/진행률) 필요 시 조정
- [ ] 찜 버튼 등 카드 인터랙티브 요소 터치 타겟 크기 검토

## 평가(통과) 기준
- `docker compose up -d` + `./gradlew bootRun`으로 로컬 기동 후, 브라우저를 모바일 뷰포트(약 375px, 414px)로 열어:
  - 헤더에서 검색창이 로고 바로 아래(또는 그에 준하는 상단 우선순위)에 오는지, 로그인/로그아웃 버튼이 알림벨·찜 아이콘과 높이가 맞는지 육안 확인
  - 상품 목록에서 카드를 탭했을 때 hover 리프트 효과가 다음 탭 전까지 남아있지 않는지 확인
  - 상품 카드 2열 레이아웃에서 가격/판매자/진행률 텍스트가 겹치거나 어색하게 잘리지 않는지 확인
- 데스크톱(1280px 이상) 뷰포트에서 기존 레이아웃에 회귀가 없는지 확인
- 기존 `docs/dev/frontend/mobile-fixes/design.md`에 정리된 이전 수정 사항(썸네일 sticky, 알림 패널 잘림)과 충돌 없는지 확인
