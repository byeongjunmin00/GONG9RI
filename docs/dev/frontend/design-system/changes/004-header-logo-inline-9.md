# 헤더 로고를 워드마크 "9" 자리에 인라인 삽입

대상: frontend/design-system     <!-- 완료 시 docs/dev/frontend/design-system/changes/로 이동 -->
담당: 전용운

## 배경 / 요구

현재 헤더(`partials/header.html`)는 왼쪽에 별도 로고 아이콘 이미지(`logo-icon.png` — 라쿤이 몸을 말아 숫자 "9" 모양을 이루는 라인아트)를 두고, 그 옆에 "GONG9RI" 텍스트 워드마크를 따로 배치한다. 텍스트 안의 "9"만 `.text-gradient`(브랜드 그라디언트)로 강조돼 있다.

사용자 요청: 아이콘이 이미 숫자 9 모양이므로, 별도로 두지 말고 워드마크의 "9" 글자 자리에 이 로고 이미지를 끼워 넣어 `GONG` + [로고] + `RI`가 한 덩어리의 로고타입처럼 자연스럽게 보이게 한다.

**시안 확인 완료(2026-08-20)**: 실제 헤더 배경·글꼴(Pretendard)·비율을 그대로 가져온 HTML 목업으로 크기/위치 4가지(A~D)와 색상 2가지(원래 그라디언트/더 어둡게 조정)를 사용자에게 직접 보여주고 아래로 확정했다.
- **크기/위치 → D안(절충안)** 채택: 글자를 1.4rem→1.6rem으로 살짝 키우고, 로고를 텍스트 기준 1.35em(≈그 폰트 크기의 135%)로 살짝 크게 잡아 위로 살짝만 튀어나오게 한다.
- **색상 → 원래 `--gradient-brand` 그대로** 채택. 더 어둡게 조정한 변형은 실제로 렌더링해보니 로고가 잘 안 보인다는 피드백을 받아 폐기했다(원인은 색의 어둡기 자체보다, 아래에 적은 "얇은 라인아트를 작게 축소" 문제일 가능성이 큼 — 그래도 사용자가 최종적으로 원래 색을 선택).

## 설계

1. **마크업 구조**: `.site-header__logo`의 선행 `<img>`를 제거하고, `.site-header__wordmark` 안에서 텍스트 "9"(`<span class="text-gradient">9</span>`) 자리를 로고 이미지로 교체한다 (`GONG` + `<img>` + `RI` 순서, 하나의 워드마크 안에 인라인으로 위치).
2. **접근성**: 스크린리더가 브랜드명을 계속 "GONG9RI"로 읽도록, 삽입되는 이미지에 `alt="9"`를 준다("GONG" 텍스트 + "9" 대체텍스트 + "RI" 텍스트가 순서대로 읽혀 "GONG9RI"가 된다). 별도 `aria-label`로 전체를 가리는 방식은 쓰지 않는다(불필요한 중복).
3. **색상 — 원래 `--gradient-brand` 그대로**: 기존 "9"와 동일하게 `--gradient-brand`(오렌지→코랄→핑크→퍼플)를 그대로 쓴다. 새 토큰을 추가하지 않는다(어둡게 조정한 변형은 시안 검토 후 폐기).
   - CSS 구현 방향: `<img>`가 아니라 PNG를 CSS `mask-image`(+`-webkit-mask-image` 접두사)로 불러와 알파 채널만큼만 배경(`--gradient-brand`)을 노출시키는 방식을 쓴다.
   - **주의(시안에서 발견)**: 원본 아이콘이 얇은 라인아트라, 인라인 크기(30~40px대)로 축소하면 선이 흐릿하게 보일 수 있다. 시안에서는 `filter: drop-shadow(...)`를 여러 방향으로 겹쳐 선을 굵게 보정했다 — Generate에서도 실제 렌더링을 보고 이 보정(또는 다른 방식)이 필요한지 판단한다.
4. **크기/정렬 — D안(절충안) 확정**: 워드마크 전체 폰트 크기를 1.4rem → **1.6rem**으로 살짝 키우고, 로고 이미지는 그 폰트 크기 기준 **1.35em**(가로세로 비율은 원본 유지) 높이로 텍스트보다 살짝 크게 잡아, 귀 부분만 다른 글자의 위쪽 높이보다 살짝 위로 튀어나오게 한다(형태 손실 절대 금지 — 잘리거나 뭉개지지 않는다).
   - 확인됨: 헤더(`.site-header__inner`, `layout.css:46-54`)는 `min-height`만 지정돼 있고 `overflow: hidden`이 없어, 아이콘이 살짝 위로 튀어나와도 잘리지 않는다.
5. **에셋**: `logo-icon.png` 원본 캔버스(243×305px)에 알파 기준 약 12px 여백이 있다 — 여백을 크롭한 자산(약 219×305px)을 새로 만들어 쓴다(시안 제작 과정에서 이미 한 번 크롭해 확인함).
6. **영향 파일**: `partials/header.html`(마크업), `css/components.css`(아이콘 크기·마스크 스타일). `css/tokens.css`/`css/layout.css`는 건드리지 않는다(새 색상 토큰 불필요, 레이아웃 구조 불변 원칙 유지 — 헤더 높이는 `min-height`라 별도 수정 불필요할 것으로 예상되나 Generate에서 실측 확인).

## 하지 않는 것

- `--gradient-brand`/`--gradient-brand-soft` 값 자체는 변경하지 않는다(다른 컴포넌트에서 계속 쓰임). 새 색상 토큰도 추가하지 않는다(어둡게 조정한 변형 폐기).
- `css/layout.css` 구조(그리드 컬럼, 헤더 단수 등)는 건드리지 않는다.
- 아이콘 형태를 다시 그리거나 리디자인하지 않는다(기존 `logo-icon.png` 라인아트 그대로 사용, 여백만 크롭).

## 태스크

- [ ] `images/logo-icon.png` 여백(약 12px) 크롭한 신규 에셋 준비 (예: `images/logo-icon-inline.png`, 약 219×305px)
- [ ] `partials/header.html` — 선행 `<img>` 제거, 워드마크를 `font-size: 1.6rem`으로, "9" 자리를 로고 이미지로 교체(`alt="9"`)
- [ ] `css/components.css` — 인라인 로고 이미지 크기(1.35em, 원본 비율 유지)/정렬(살짝 위로 튀어나오게)/마스크(`--gradient-brand`)/선 얇음 보정 스타일 추가
- [ ] 브라우저 확인 — 데스크톱/모바일 브레이크포인트 둘 다, 다른 헤더 요소(검색바/알림/로그인버튼)와 안 겹치는지, 로고 형태가 실제로 잘 보이는지
- [ ] `docs/dev/frontend/design-system/design.md` 갱신, ongoing → changes 채번 이동

## 평가(통과) 기준

- `./gradlew test` 통과.
- 브라우저 육안 확인: "GONG"+로고+"RI"가 하나의 로고타입처럼 이어져 보이는가, 로고 색이 배경과 충분히 대비되는가, 라쿤 형태(귀/수염/꼬리)가 전혀 잘리지 않고 다 보이는가.
- 모바일 폭(헤더가 wrap되는 브레이크포인트)에서도 아이콘이 안 깨지는가.
- 브라우저 콘솔 에러 없음.

## 리스크 / 전제

- `header.html`은 모든 페이지가 공유하는 partial이라 이 변경은 전역에 즉시 반영된다.
- 같은 개념(`frontend/design-system`) 아래 `docs/dev/ongoing/design-system-sharp-ui.md`가 이미 진행 중이며(로그상 여러 Attempt를 거쳤으나 아직 Evaluate 통과/`changes/` 이동 전 상태) 아직 `ongoing/`에 남아 있다. 그 작업은 검색바/각진 UI 영역이라 이번 로고 변경과 파일 수준(`header.html`)에서 겹치는 부분은 있지만 다른 위치(로고 영역 vs 검색바 영역)라 실질 충돌 가능성은 낮다. 다만 두 작업 다 같은 `design.md`를 갱신 대상으로 하므로, 어느 쪽이 먼저 완료(Evaluate 통과)되는지에 따라 design.md 갱신 순서를 맞춰야 한다.
- CSS `mask-image`는 브라우저 접두사(`-webkit-mask-image`)가 필요하다 — 이 프로젝트 범위에서 구형 브라우저 미지원은 무시 가능하다고 가정한다(사용자 확인 전제).
- 원본 아이콘이 얇은 라인아트라 인라인 크기로 축소하면 선이 흐릿해 보일 위험이 시안 검토 중 실제로 확인됐다 — `filter: drop-shadow(...)` 겹치기로 보정했으나, 실제 헤더(실제 폰트 렌더링·화면 배율)에서 다시 확인이 필요하다.
