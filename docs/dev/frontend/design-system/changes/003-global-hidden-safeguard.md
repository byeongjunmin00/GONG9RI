# 네이티브 `[hidden]` 전역 안전장치

대상: frontend/design-system
담당: 민병준

## 배경 / 요구

`display`를 선언하는 클래스를 가진 요소에 JS가 `hidden` 속성을 걸어도 안 숨겨지는 CSS 명시도 함정을 이 프로젝트에서 **여섯 번** 겪었다:

| # | 클래스 | 어떻게 드러났나 |
|---|---|---|
| 1 | `.btn` | — |
| 2 | `.product-detail` | — |
| 3 | `.site-header__auth` | — |
| 4 | `.chat-widget*` | — |
| 5 | `.card-seller-trust` | 리뷰 0건 판매자에게도 신뢰배지가 항상 노출 |
| 6 | `.site-header__wishlist-link` | 판매자 계정에 구매자 전용 찜 아이콘 노출 |

매번 개별 `.클래스[hidden] { display: none }` 규칙을 사후에 추가하는 식으로 대응했고, 그렇게 쌓인 보정 규칙이 **17개**다.

다섯 번째(`.card-seller-trust`) 트러블슈팅 회고에 이미 *"다음에 또 나오면 전역 안전장치(`[hidden]{display:none !important}`)를 검토하자"*고 적어뒀는데, 실제 검토를 하지 않아 여섯 번째를 맞았다. 이번에 실제로 도입한다.

## 설계

`base.css`에 전역 규칙 한 줄:

```css
[hidden] {
  display: none !important;
}
```

### `!important`가 정당한 근거

`!important`는 보통 피해야 하지만, 여기서는 **"`hidden` 속성이 걸린 요소는 예외 없이 숨겨진다"가 뒤집힐 이유가 없는 규칙**이라 정당하다고 판단했다. 문제가 되는 건 `!important`가 인라인 스타일까지 이긴다는 점인데, 도입 전에 다음을 전수 확인했다:

| 확인 항목 | 결과 |
|---|---|
| `style.display`를 직접 조작하는 JS | **0건** (인라인 스타일과 충돌 여지 없음) |
| `hidden` 토글 방식 | 전부 `el.hidden = true/false`로 일관 (`setAttribute`/`removeAttribute` 직접 호출 0건) |
| `display`에 `!important`를 쓰는 다른 규칙 | **0건** (`!important` 간 우선순위 다툼 없음) |
| `[hidden]` 요소를 다시 보이게 하려는 CSS 규칙 | **0건** |
| 기존 17개 보정 규칙의 선언 값 | 전부 `display: none` — 전역 규칙과 의도가 동일 |

로드 순서(`tokens → base → layout → components`)는 이 규칙에 영향을 주지 않는다 — `!important` 선언은 순서와 무관하게 일반 선언을 이긴다.

### 기존 17개 규칙을 같은 커밋에서 지우지 않은 이유 (2단계로 나눔)

전역 규칙이 생겼으므로 개별 보정 규칙은 전부 중복이다. 그래도 같은 커밋에서 지우지 않았다 — **전역 규칙이 프로덕션에서 실제로 동작하는 걸 확인한 뒤에 정리해야 문제가 생겼을 때 원인 분리가 된다.** 둘을 한 번에 바꾸면 "전역 규칙이 안 먹은 건지, 지운 개별 규칙이 필요했던 건지" 구분이 안 된다.

## 평가(통과) 기준

- 전역 규칙이 프로덕션 `base.css`에서 실제로 서빙된다.
- 기존에 `hidden`으로 숨기던 요소들이 계속 정상적으로 숨겨진다(전역 규칙이 상위집합이라 회귀 위험 없음).
- 앞으로 `display`를 선언하는 새 컴포넌트에서 이 함정이 재발하지 않는다.

## 배운 것

회고에 "다음에 또 나오면 검토하자"고 적어두는 것만으로는 부족했다 — 그 사이 새 컴포넌트를 여럿 만들면서 검토를 실제로 하지 않았고, 그래서 같은 버그를 한 번 더 맞았다. **개별 사후 수정을 반복하는 패턴이 보이면, 그 시점에 구조적 해결을 실행해야 한다.**
