# 디자인 시스템 색상/브랜드 요소 개편 (쇼케이스 페이지 우선, 무신사 톤 참고)

대상: frontend/design-system     <!-- 완료 시 docs/dev/frontend/design-system/changes/로 이동 -->
담당: 전용운

## 배경 / 요구

- 사용자(전용운, `frontend/design-system` 원래 담당자) 요청: 기존 디자인 시스템(`docs/dev/frontend/design-system/design.md`, 오프화이트 배경 + 오렌지/코럴/핑크/퍼플 웜 그라디언트의 "인스타 인플루언서" 톤앤무드)을 무신사(대형 패션 이커머스) 톤을 참고해 개편한다.
- **요구사항이 여러 차례 바뀌었고, 이 문서는 최종 확정 범위를 반영한다.** 진행 경과:
  1. (최초 요구) "색상은 그대로, 레이아웃 구조만 개편" → 이후 **폐기**.
  2. 상세 페이지(`product.html`) 포함 검토 → 이후 **레이아웃 개편 자체를 접으면서 같이 폐기**(아래 5번 참고).
  3. 검색창 UI 자리 추가 — 백엔드 API 없지만 프론트 UI 먼저 배치(입력만 되는 순수 UI). **유지.**
  4. 찜하기(위시리스트) UI 자리 추가 — 백엔드 API는 나중에 만들 예정이니 지금은 UI 배치만. **유지.**
  5. 색상/톤 변경으로 전환 — "색상은 그대로"였던 최초 결정을 뒤집는다. 무신사가 쓰는 것으로 보이는 흰색/흰색에 가까운 회색/검정에 가까운 회색의 3톤 무채색 체계를 참고하되, **검정에 가까운 회색 자리를 어두운 쑥색(다크 세이지 그린)으로 대체**한다. 기존 오렌지/코럴/핑크/퍼플 웜 그라디언트는 **완전히 제거**한다. **유지.**
  6. **로고를 텍스트에서 이미지 아이콘으로 교체(결정 갱신)** — 처음엔 "9"에만 걸린 `.text-gradient` 차등 강조만 없애고 텍스트는 유지할 계획이었으나, 사용자가 직접 만든 로고 이미지(라쿤 얼굴 모양의 "9" 형상 라인아트 아이콘)를 제공하며 **헤더 좌측상단의 텍스트 로고(`GONG9RI`)를 이 아이콘 이미지로 완전히 교체**하고, 기존과 동일하게 클릭 시 메인 페이지(`/`)로 이동하는 링크 기능은 유지하기로 결정했다.
     - 사용자가 준 원본 파일은 배경 제거(누끼) 작업을 거쳤다고 했으나 실제로는 `.jpg`로 저장돼 있어 투명도가 없었고(JPEG는 알파 채널 미지원), 체크무늬 배경이 실제 픽셀 색상으로 박혀 있었다. 픽셀 색상값을 분석해(라인아트 부분 RGB≈97, 체크무늬 배경 RGB≈179~229) 배경을 진짜 투명으로 변환하고, 배경 제거 도구가 남긴 것으로 보이는 워터마크 흔적까지 제외되도록 아이콘 영역만 타이트하게 크롭해 `src/main/resources/static/images/logo-icon.png`로 저장했다.
     - 이 이미지는 원본의 중간 회색 라인아트 색(RGB≈97,97,95)을 그대로 유지한 래스터 PNG다 — 정확한 다크 세이지 그린 브랜드 색으로 재색상화하지는 않았다(요청받으면 후속으로 처리 가능).
     - 푸터(`partials/footer.html`)의 텍스트 로고는 이번 요청이 "좌측상단"(헤더)으로 한정돼 있어 **이번 범위에서는 그대로 텍스트 유지**로 가정했다 — 푸터도 아이콘으로 바꿀지는 확인이 필요하면 알려달라.
     - **헤더 배경 위 로고 색상(추가 결정)**: 헤더 배경이 새 팔레트의 다크 세이지 그린 계열이 될 예정이라, 원본 회색(RGB≈97) 로고를 그대로 쓰면 배경과 대비가 약하다. 그래서 **알파(투명도)는 그대로 두고 불투명 픽셀만 흰색(255,255,255)으로 바꾼 버전**을 별도로 만들어 `src/main/resources/static/images/logo-icon-white.png`로 저장했다 — 헤더(어두운 배경)에는 이 흰색 버전을, 밝은 배경(쇼케이스 본문, 푸터 등)에는 기존 회색 버전(`logo-icon.png`)을 쓴다.
  7. 폰트 변경 — 무신사가 쓰는 것과 같거나 유사한 폰트 요청. 무신사의 실제 폰트 파일(자체 커스텀일 가능성)을 그대로 가져다 쓰는 것은 자산 직접 복사라 하지 않는다. 대신 이미 쓰고 있는 라이선스 프리 폰트 'Pretendard'로 헤딩·본문을 통일한다(현재 헤딩은 둥글고 화사한 'Poppins' — 새 톤과 안 맞음). **유지.**
  8. **범위 축소(최종 결정)** — 사용자가 "레이아웃은 바꾸지 않는 걸로 축소"하고 "쇼케이스 페이지(`design-system.html`)부터 먼저 만들자"고 결정했다. 즉:
     - 헤더 2단 구조화, 카드 그리드 밀도/브레이크포인트 재정의, 푸터 다단 구조화, 상세 페이지 이미지-구매정보 2컬럼 배치 등 **레이아웃 구조 변경은 전부 이번 계획에서 뺀다.** 기존 1단 헤더, 기존 그리드 컬럼 수, 기존 푸터 2블록, 기존 상세 페이지 세로 1컬럼 구조는 그대로 유지한다.
     - 이번 계획(1단계)의 구현 범위는 **디자인 시스템 계층 + `design-system.html` 쇼케이스 페이지**로 한정한다. 메인 페이지(`index.html`)·상세 페이지(`product.html`)에 실제로 반영하는 것은 **이번 계획에 포함하지 않고**, 쇼케이스 페이지에서 톤을 확인·승인받은 뒤 별도 후속 계획으로 진행한다.
- 명시적으로 확인된 저작권 제약(변하지 않음): 무신사의 로고·이미지·문구·CSS·HTML·폰트 파일을 그대로 복사하지 않는다. 색상 배합/폰트 스타일처럼 업계에 흔히 쓰이는 "아이디어" 수준만 참고한다.
- 이번 작업은 신규 디자인 시스템 구축이 아니라 **기존 산출물(`css/tokens.css`, `css/base.css`, `css/components.css`, `design-system.html`)의 색상/타이포/브랜드 요소 개편**이며, `docs/dev/frontend/design-system/design.md`(현재 SSOT)를 베이스라인으로 삼는다. `css/layout.css`는 이번 범위에서 다루지 않는다(레이아웃 구조 변경 없음).

## 조사 결과 (베이스라인 파악)

- **현재 색상/폰트 토큰** (`css/tokens.css`):
  - 무채색 베이스: `--color-bg: #FFF9F5`(오프화이트), `--color-surface: #FFFFFF`, `--color-border: #F0E4DC`, `--color-text: #2B2530`(차콜빛 플럼).
  - 브랜드 액센트: `--color-orange`/`--color-coral`/`--color-pink`/`--color-purple` 4색 + 이를 조합한 `--gradient-brand`, `--gradient-brand-soft` — **이번에 전부 제거 대상**.
  - 그림자(`--shadow-sm/md/lg`)도 핑크/퍼플 색이 섞인 `rgba(255,77,141,...)`/`rgba(139,92,246,...)` 틴트를 쓰고 있어, 그라디언트를 없애면 그림자 색상도 같이 무채색/쑥색 계열로 바꿔야 색이 겉돌지 않는다.
  - 상태 뱃지용 시맨틱 컬러(`--color-success`/`--color-warning`/`--color-danger`, 공구 모집중/성사/미성사 표시)는 브랜드 무드가 아니라 **기능적 상태 표시**라 이번 색상 개편 대상에서 제외한다 — 단, 새 배경 위에서 여전히 잘 읽히는지는 쇼케이스에서 확인한다.
  - 헤딩 폰트: `--font-heading`이 `'Poppins'`를 1순위로 쓰고 있다(구글 폰트, 둥글고 화사한 인상). 본문 폰트 `--font-body`는 이미 `'Pretendard'`.
- **`.text-gradient` 클래스 사용 현황** (`grep` 확인): `css/base.css`에 클래스 하나로 정의돼 있고, `partials/header.html`·`partials/footer.html`의 로고(`GONG<span class="text-gradient">9</span>RI`)뿐 아니라 `index.html`/`login.html`/`signup.html`/`buyer/mypage.html`/`seller/mypage.html`/`seller/products/{new,edit}.html`/`forgot-password.html`/`reset-password.html`/`design-system.html`의 페이지 제목 강조 문구에도 광범위하게 쓰이고 있다.
  - **범위 축소에 따른 처리 방침**: `.text-gradient` 클래스 자체(`base.css`)와 `tokens.css`의 색상 변수는 **CSS 전역**이라, 이번에 값을 바꾸면 `design-system.html` 밖의 다른 모든 페이지(메인/상세/체크아웃/마이페이지/로그인 등)에도 자동으로 함께 반영된다 — 이건 페이지 마크업을 손대는 게 아니라 공용 CSS 값 교체이므로 "쇼케이스만 한다"는 결정과 모순되지 않는다(아래 "확정 범위" 참고).
  - 로고의 "9"만은 강조 자체를 없애고 단일 색으로 통일해야 하므로, `header.html`·`footer.html`의 로고 마크업에서 `<span class="text-gradient">9</span>` 래핑만 제거하는 처리가 필요하다(이 부분만 마크업 변경, 나머지는 CSS 값 변경).
- **검색/찜하기 UI를 놓을 자리**: 레이아웃 구조를 안 바꾸므로, 검색 입력창과 찜하기 버튼은 **기존 구조 안에 자연스럽게 끼워 넣는 수준**으로 쇼케이스에 예시로 보여준다(예: 검색 입력창은 헤더 쇼케이스 섹션에 컴포넌트 예시로, 찜하기 버튼은 카드 컴포넌트 예시에 아이콘 버튼으로). 실제 헤더 partial이나 카드 마크업 구조 자체를 바꾸지 않는다.

## 확정 범위 (1단계 — 쇼케이스 페이지)

- **포함**:
  - `src/main/resources/static/css/tokens.css` — 색상 토큰 전면 교체 + 헤딩 폰트 교체(레이아웃 관련 변수는 건드리지 않음).
  - `src/main/resources/static/css/base.css` — `.text-gradient` 재정의(그라디언트 → 단일 강조색).
  - `src/main/resources/static/css/components.css` — 기존 컴포넌트(버튼/뱃지/카드 등)의 **색상 값만** 새 토큰에 맞게 갱신(구조는 변경 없음) + 검색 입력창/찜하기 버튼 컴포넌트 스타일 신설.
  - `src/main/resources/static/partials/header.html` — 텍스트 로고(`GONG<span class="text-gradient">9</span>RI`)를 이미지 아이콘(`images/logo-icon-white.png`, 헤더 배경이 어두운 세이지 계열이라 흰색 버전 사용)으로 교체. 기존처럼 `<a href="/">`로 감싸 메인 페이지 이동 기능 유지. 레이아웃 구조(1단 헤더)는 그대로.
  - `src/main/resources/static/partials/footer.html` — 텍스트 로고는 이번 범위에서 유지, `.text-gradient`만 새 단일 강조색으로 자동 반영(클래스 재정의로 처리, 마크업은 안 건드림).
  - `src/main/resources/static/images/logo-icon.png`, `images/logo-icon-white.png` — 사용자가 제공한 라쿤 모양 "9" 로고 원본(JPG, 실제로는 알파 없이 체크무늬가 픽셀로 박혀 있었음)을 픽셀 색상 분석으로 진짜 투명 PNG로 변환하고 워터마크 잔여물을 제외해 크롭한 회색 버전(`logo-icon.png`), 그리고 헤더용으로 같은 알파를 유지한 채 불투명 픽셀만 흰색으로 바꾼 버전(`logo-icon-white.png`). 이미 이번 대화에서 생성 완료.
  - `src/main/resources/static/design-system.html` — 새 색상/폰트/로고를 반영한 쇼케이스 갱신(로고 영역은 회색 버전 사용 — 쇼케이스 배경은 밝음) + 검색 입력창·찜하기 버튼 컴포넌트 예시 추가.
- **색상/로고 변경은 전역 적용**: `tokens.css`/`base.css`의 값과 `header.html`/`footer.html`의 로고는 모든 페이지가 공유하므로, 메인/상세/체크아웃/마이페이지/로그인 등 다른 페이지에도 새 색상·폰트·단일색 로고가 자동으로 반영된다. 이 페이지들의 **레이아웃 구조나 개별 마크업은 건드리지 않지만**, 색상이 바뀐 채로 깨지지 않는지는 회귀 확인 대상이다.
- **이번 계획에 포함하지 않음(후속 계획으로 분리)**:
  - 헤더 2단 구조화, 카드 그리드 밀도/브레이크포인트 재정의, 푸터 다단 구조화, 상세 페이지 2컬럼 배치 등 **레이아웃 구조 변경 전부.**
  - 검색 입력창·찜하기 버튼을 `index.html`(메인 그리드)·`product.html`(상세) 실제 페이지에 반영하는 것 — 쇼케이스에서 컴포넌트로만 보여주고, 실제 페이지 적용은 사용자가 쇼케이스를 보고 승인한 뒤 별도 계획으로 진행한다.
  - 찜하기/검색 기능 자체(백엔드 API 없음, 이후 별도 작업).
  - `js/main.js`, `js/product.js`, `js/header-auth.js`, `js/chat-widget.js`, `js/include.js` — 이번 범위에서 변경 없음(쇼케이스 정적 페이지 갱신에는 JS 로직 변경이 필요 없다).

## 참고할 무신사 톤 패턴 → GONG9RI 적용 방향 (색상/타이포/UI 요소만, 구조 제외)

무신사의 로고·이미지·문구·CSS·HTML·폰트 파일은 참고하지 않는다(자산 직접 복사 금지). 아래는 **색 배합·타이포·UI 요소 아이디어** 수준까지만 참고 대상이며, 레이아웃 구조는 참고 대상에서 뺐다.

| # | 무신사류 패턴 | GONG9RI 현재 상태 | 적용 방향 |
|---|---|---|---|
| 1 | 무채색 베이스 팔레트 — 흰색 / 흰색에 가까운 회색 / 검정에 가까운 회색 3톤 | 오프화이트 배경 + 오렌지/코럴/핑크/퍼플 웜 그라디언트 | **색상/톤을 전면 교체**한다. 흰색(`--color-surface`)·연한 회색(`--color-bg`/`--color-border`) 2톤은 무신사류 그대로 채용하고, "검정에 가까운 회색" 자리를 **어두운 쑥색(다크 세이지 그린)**으로 바꿔 텍스트/강조 색으로 쓴다. 기존 웜 그라디언트와 그림자 틴트는 완전히 제거한다. 정확한 색상 값(쑥색 hex 등)은 Generate 단계에서 확정한다. |

### 하지 않는 것

- **레이아웃 구조 변경 안 함** — 헤더 2단 구조화, 그리드 밀도/브레이크포인트 재정의, 푸터 다단 구조화, 상세 페이지 2컬럼 배치 등 일체의 구조 변경을 하지 않는다. `css/layout.css`는 이번 범위에서 건드리지 않는다.
- **메인/상세 페이지 실제 반영 안 함** — 검색 입력창·찜하기 버튼은 쇼케이스 컴포넌트로만 만들고, `index.html`/`product.html`에 실제로 넣는 것은 후속 계획으로 미룬다.
- **무신사 자산 직접 복사 안 함** — 로고·이미지·문구·CSS·HTML·폰트 파일을 베끼지 않는다. 색 배합/폰트 스타일 같은 업계 통용 수준만 참고한다.

- **상태 뱃지 색상(성사/모집중/미성사) 변경 안 함** — 기능적 색상이라 이번 브랜드 톤 개편 대상이 아니다.
- **JS 로직 변경 없음** — `js/main.js`, `js/product.js`, `js/header-auth.js`, `js/chat-widget.js`, `js/include.js` 등 어떤 JS 파일도 수정하지 않는다.

## 리스크 / 전제

- **전역 색상 토큰 교체로 인한 광범위 회귀 가능성**: `tokens.css`/`base.css`의 색상 변수와 `.text-gradient`는 CSS 특성상 쇼케이스 밖 모든 페이지(메인/상세/체크아웃/마이페이지/로그인 등)에도 즉시 반영된다. 오렌지/코럴/핑크/퍼플을 참조하던 곳(버튼/뱃지/그림자 등)을 빠짐없이 찾아 바꾸지 않으면 일부 요소만 옛 색이 남거나 대비가 깨질 수 있다.
- **동작하지 않는 검색창/찜하기 버튼의 혼란 가능성**: 쇼케이스에서 눌러도 아무 일도 안 일어나므로, "이건 컴포넌트 예시일 뿐 실제 페이지에는 아직 없다"는 게 쇼케이스 안에서 명확해야 한다(라벨/설명 문구로 처리, 정확한 방식은 Generate 재량).
- **상태 뱃지 대비 저하 가능성**: 배경이 오프화이트 웜톤에서 무채색+쑥색 계열로 바뀌면, 색상 값이 그대로인 상태 뱃지의 가독성이 미세하게 달라질 수 있다 — 확인만 하고 수정은 필요시에만.
- **1단계-2단계 사이 과도기적 불일치**: 이번 1단계가 끝나면 쇼케이스와 전역 색상/폰트/로고는 새 톤이지만, 검색창/찜하기 UI와 레이아웃 구조는 메인/상세 페이지에 아직 반영되지 않은 상태로 남는다. 이건 의도된 단계적 진행이며, 사용자가 쇼케이스를 승인하면 후속 계획으로 이어간다.
- **정성적 목표 검증의 한계**: "무신사 톤을 참고하되 자산은 베끼지 않았다"는 목표는 정성적 판단이라 자동화된 기준으로 완결되지 않는다.
- **로고 이미지 크기/비율 조정 필요**: `logo-icon-white.png` 원본은 243×328(세로가 긴 비율) 크기다. 헤더 높이(`--header-height: 72px`)에 맞춰 `<img>`의 `height`를 제한하고 `width: auto`로 비율을 유지해야 다른 nav 항목과 어울리는 크기가 된다 — 정확한 px 값은 Generate에서 정한다.
- **접근성**: 텍스트 로고를 이미지로 바꾸므로 `<img alt="GONG9RI">`(또는 동등한 텍스트)를 반드시 넣어야 스크린리더에서 브랜드명이 사라지지 않는다.
