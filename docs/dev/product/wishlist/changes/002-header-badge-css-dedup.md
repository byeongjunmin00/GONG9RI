# 헤더 찜 뱃지 CSS 중복 제거

대상: product/wishlist
담당: 전용운

## 배경 / 요구

코드리뷰(2026-08-20, 병합된 15개 커밋 리뷰)에서 발견: `layout.css`의 `.site-header__wishlist-badge`
(찜 개수 뱃지)와 `.site-header__notifications-badge`(알림 벨 개수 뱃지)가 15개 선언을 완전히
동일하게 복붙해서 각자 따로 갖고 있었다(주석에도 "알림 벨과 동일한 스타일"이라고 스스로 적어놨음).
디자인을 하나만 바꾸고 다른 하나를 깜빡하면 두 뱃지가 어긋나는 문제가 생길 수 있다.

## 설계

두 선택자를 콤마로 묶어 하나의 규칙으로 합친다(`.site-header__wishlist-badge,
.site-header__notifications-badge { ... }`) — 선언 내용은 완전히 동일했으므로 렌더링 결과에
변화가 없는 순수 리팩터링이다. HTML/JS는 전혀 건드리지 않는다.

`header-notifications.js`/`header-wishlist-badge.js`의 JS 쪽 뱃지 렌더링 함수(9+ 상한 처리, 8줄)도
똑같이 중복돼 있었으나, 이건 공유 파일을 새로 만들어야 하고 그러려면 헤더가 삽입되는 17개 페이지의
`<script>` 태그를 전부 손대야 한다 — 최근 `824fe91`(상품 상세 리디자인)이 공용 CSS 클래스를 건드려
결제·상품등록 페이지까지 함께 깨진 사고가 있었던 직후라, 8줄 중복을 없애자고 17개 페이지를 건드리는
건 이득 대비 위험이 크다고 판단해 사용자와 상의 후 보류했다(그냥 둔다).

## 태스크

- [x] `layout.css`의 두 뱃지 규칙을 콤마 선택자로 합침
- [x] JS 쪽 중복은 보류(사용자 판단)

## 평가(통과) 기준

- CSS 중괄호 균형 확인, 렌더링 결과(선언값) 변화 없음

## 실행 결과

`layout.css`의 두 규칙을 합쳤다(선언 15개가 완전히 동일했음을 사전에 직접 대조 확인). 중괄호
균형(42:42) 확인. 순수 CSS 선택자 병합이라 브라우저 렌더링 결과에 변화가 없어 별도 시각 확인은
생략했다. JS 함수 중복은 위 이유로 이번엔 손대지 않기로 확정.
